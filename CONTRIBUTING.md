# Contributing to SEO Growth Systems

Thank you for your interest in contributing to **SEO Growth Systems**.

This repository is maintained as a practical knowledge base for **SEO, GEO, AI Search Visibility and search-to-revenue measurement**.

Contributions are welcome when they improve the accuracy, usefulness or practical application of the frameworks.

---

## 🎯 Contribution Philosophy

The goal of this repository is not to collect SEO tips or publish content for volume.

Contributions should help practitioners build better systems around:

**Technical SEO → Content → Authority → Search Visibility → AI Visibility → Conversion → Measurement**

Preference is given to contributions that are:

- Practical
- Evidence-backed
- Clearly explained
- Reproducible where possible
- Useful to practitioners
- Based on real implementation or testing

---

## ✅ Contributions We Welcome

### 1. Corrections & Updates

Search engines and AI-powered discovery systems change continuously.

Corrections are welcome when existing information has become:

- Outdated
- Technically inaccurate
- Incomplete
- Misleading
- Inconsistent with current platform documentation

When possible, include a link to the relevant official documentation or supporting evidence.

---

### 2. Technical SEO Implementation Examples

Useful examples may include:

- Crawlability configurations
- Indexation controls
- Canonical implementations
- Redirect strategies
- Structured data examples
- JavaScript SEO considerations
- Internal linking architectures
- Website migration procedures
- Core Web Vitals improvements

Examples should explain **why the implementation is useful**, not simply provide code.

---

### 3. GEO & AI Search Experiments

We welcome documented experiments related to:

- Generative Engine Optimization
- AI Search Visibility
- LLM citation behavior
- Entity understanding
- Content structure
- Passage-level answerability
- Citation-worthy assets
- AI search prompt testing
- Brand/entity visibility
- AI visibility measurement

Because this area is evolving quickly, observations should be clearly distinguished from established facts.

For experiments, please include where possible:

```text
Hypothesis
↓
Method
↓
Prompts / Queries
↓
Platforms Tested
↓
Observations
↓
Limitations
↓
Conclusion
```

Do not present isolated observations as universal AI ranking factors.

## 🚫 Contributions We Do Not Accept

Please do not submit:

- Promotional backlinks
- Guest-post requests
- Link-exchange requests
- Affiliate links
- Keyword-stuffed content
- Generic SEO tips
- Unsupported ranking-factor claims
- Fabricated statistics
- Fabricated case studies
- AI-generated content submitted without meaningful review
- Duplicate content
- Promotional agency content
- Unrelated tools or software promotions

This repository is not intended to be used as a backlink-placement platform.

## 🔬 Evidence Standards

SEO contains a mixture of documented behavior, observed behavior and industry hypotheses.

Contributions should make this distinction clear.

### Documented

Supported by official documentation from platforms such as search engines or relevant technology providers.

### Observed

Behavior repeatedly observed through testing, implementation or measurement.

### Experimental

A hypothesis currently being tested.

### Opinion

A strategic interpretation or recommendation based on experience.

Where possible, provide supporting sources.

---

## 🤖 AI Search & GEO Contributions

AI-powered search systems are evolving rapidly.

Contributors should avoid statements such as:

> "This guarantees an AI citation."

> "This is an LLM ranking factor."

> "Doing this will make ChatGPT recommend your business."

unless reliable evidence supports the claim.

Prefer language such as:

> "This may improve machine understanding."

> "Testing suggests..."

> "This implementation can improve entity clarity."

> "This may increase the likelihood that information can be accurately interpreted or referenced."

The objective is to build an evidence-oriented GEO knowledge base rather than speculate about undocumented algorithms.

---

## 🔐 Privacy & Client Information

Never submit:

- Client credentials
- Private analytics data
- Personal information
- API keys
- Access tokens
- Confidential business information
- Private CRM data
- Unredacted customer information

Real-world examples should always be appropriately anonymized or sanitized.

## 🛠 How to Contribute

### Small Correction

For typos, broken links or minor corrections:

1. Fork the repository.
2. Edit the relevant file.
3. Create a pull request.
4. Explain what you changed.

### Larger Contribution

For new frameworks, templates or significant changes:

1. Open an Issue first.
2. Explain the proposed contribution.
3. Describe why it would improve the repository.
4. Include supporting evidence or examples where relevant.
5. Wait for feedback before investing significant time in the contribution.

---

## 📝 Pull Request Guidelines

A good pull request should explain:

### What changed?

Describe the change clearly.

### Why?

Explain the problem or opportunity.

### Evidence

Provide documentation, testing or observations where relevant.

### Impact

Explain how the contribution improves the framework or helps practitioners.

---

## 📁 File Naming

Use lowercase filenames with hyphens.

Good:

```text
technical-seo-audit-template.md
geo-prompt-testing-template.md
seo-reporting-template.md
```

Avoid:

```text
Technical SEO Template FINAL.md
new_file_v2.md
SEOStuff.md
```

---

## ✍️ Writing Style

Please keep contributions:

- Clear

- Professional
- Vendor-neutral where possible

- Focused on implementation
